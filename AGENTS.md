# Обзор проекта
Проект представляет собой сервис для учета личных финансов. Пользователь может сохранять информацию о всех денежных поступлениях и затратах и на основе этого получать определенную аналитику в виде графиков, схем и таблиц.
Подразумевается, что проект будет запускаться локально, чтобы избежать утечки данных о финансовых средствах во внешнюю среду. 

# Принцип работы проекта
На локальной машине находится файл sqlite (путь сохранения указан в config.py и .env в переменной FINANCE_TRACKER_DB_PATH) с данными о доходах и расходах пользователя. Сервис читает данные из файла sqlite и может добавлять в него новые записи. На основе полученной информации строятся графики, приводятся схемы или таблицы за указанный пользователем период.

# Архитектура проекта

- src/ - корневая директория, в которой хранятся все модули, необходимые проекту для работы
- migrations/ - директория с версиями миграций для БД. Предназначена для фиксирования изменений в структуре БД и генерации скриптов по созданию/удалению, а также изменению таблиц
- docs/ - директория с документацией
- src/core/ - поддиректория для инфраструктурного кода. В ней может храниться код по считыванию конфигураций из .env или .yaml файлов, работа с базой данных и общие методы для разных модулей
- src/core/configuration - модуль для работы с конфигурациями. Основной файл - config.py.
- src/core/database - модуль по работе с базой данных
- tests/ - директория для тестов. Делится на интеграционные: tests/integration/ и юнит-тесты tests/unit/. Архитектура модулей в тестах должна повторять архитектуру в корне src/
- .env и .env.example - файл с конфигурационными данными для БД. Файл .env нельзя коммитить.

Структура проекта:
```
finance-tracker/
├── docs/                          # документация и задачи
├── migrations/                    # миграции Alembic (env.py, versions/)
├── src/
│   ├── main.py                    # точка входа (FastAPI-приложение)
│   └── core/
│       ├── configuration/
│       │   └── config.py          # чтение настроек из .env
│       └── database/
│           ├── db.py              # запуск миграций, фабрика engine
│           └── models.py          # ORM-модели (SQLAlchemy)
├── tests/
│   ├── unit/                      # unit-тесты (зеркалят структуру src)
│   └── integration/               # интеграционные тесты (зеркалят структуру src)
├── .env.example                   # шаблон конфигурации (сам .env в .gitignore)
├── alembic.ini                    # настройки Alembic
├── pyproject.toml
├── uv.lock
└── README.md
```

***ВАЖНО!*** Иные модули проекта должны добавляться в корневую директорию src/

# Команды для работы с проектом
- `uv sync` - установка зависимостей
- `uv run python src/main.py` - запуск сервиса. При старте автоматически применяются миграции и поднимается uvicorn на хосте и порту из .env
- `uv run pytest -vvv` - запуск тестов с представлением подробного отчета
- `uv run ruff check .` - проверка код-стайла линтером
- `uv run mypy` - статическая проверка типов
- `uv run alembic upgrade head` - применить миграции вручную
- `uv run alembic revision --autogenerate -m "описание миграции"` - создать новую миграцию (применимо после изменения моделей БД, то есть редактирования файла src/core/database/models.py)
